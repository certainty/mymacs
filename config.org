This is my handcrafted configuration for GNU Emacs. It's build using a single org-mode file and tangle it to the appropriate Emacs lisp files
before use. This way I can document why I configure the things I do, for myself really. My hope is that at some point I must rely on
this documentation, because I only rarely change my configuration. That would be a nice "problem" to have.

* 1. Building Emacs and the configuration

** Build Emacs and dependencies
The =Makefile= contains targets to build all required dependencies, including Emacs itself.
I just invoke the appropriate target and wait for its completion.

#+begin_src sh
make bootstrap
#+end_src


** Tangle the configuration
This configuration is an org file which acts as source for my final configuration.
I use the =Makefile= to tangle my modules and lisp files from this single org file.

*IMPORTANT*: The tangling process will first wipe the =./modules= and =./lisp= directory, and will then go on to generate the new files.

#+begin_src sh
make tangle
#+end_src

* 3. Conventions used throughout the configuration

Guiding principles:

*Don't configure what you don't understand*
*Don't configure what you don't use*
*Keep it simple*

- Usable evil environment early (avoid to go to vanilla emacs on boot errors)
- Usable minibuffer experience early (so if I'm dropped into it during bootup errors I have some convenience)

* 4. Environment

Whenever I run Emacs in GUI mode I need to make sure that its process environment is working properly.
There are multiple existing solutions for that problem, but I like to follow a simple approach, that is a single environment file that Emacs loads on startup.
The content of the file is a single variable binding that assigns an association list to the variable ~my/env~.
The following is an *example* of this file. The real file lives inside my Emacs directory but I do not check it in.
In fact it will be ignore via =.gitignore=.

#+begin_src emacs-lisp :tangle "env.el.example"
;;; env.el --- a stable environment -*- lexical-binding: t; -*-

(setq my/env
      `((PATH . "usr/local/bin:/opt/homebrew/bin:/usr/bin:/bin")
        (GEM_HOME . "~/.gem")
        (EDITOR . "emacsclient")
        (LC_ALL . "en_US.UTF-8")
        (LANG . "en_US.UTF-8")))
#+end_src

** Load environment
This is useful / required to run a GUI Emacs with a proper environment that is stable and reproducible.
We load the environment that we defined earlier and amend the Emacs environment and exec path.

#+begin_src emacs-lisp :tangle "early-init.el"

;;; Environment setup (from env.el)
(defvar my/env nil
  "User environment key-value alist loaded from env.el.")

(let ((env-file (expand-file-name "env.el" user-emacs-directory)))
  (when (file-exists-p env-file)
    (load env-file nil t)
    (when (boundp 'my/env)
      (dolist (pair my/env)
        (let* ((key (symbol-name (car pair)))
               (val (expand-file-name (cdr pair))))
          (setenv key val)
          (when (string-equal key "PATH")
            (setq exec-path
                  (delete-dups (append (parse-colon-path val) exec-path)))))))))
#+end_src

#+begin_src emacs-lisp :tangle "init.el"

;;; Elpaca

(defvar elpaca-installer-version 0.11)
(defvar elpaca-directory (expand-file-name "elpaca/" user-emacs-directory))
(defvar elpaca-builds-directory (expand-file-name "builds/" elpaca-directory))
(defvar elpaca-repos-directory (expand-file-name "repos/" elpaca-directory))
(defvar elpaca-order '(elpaca :repo "https://github.com/progfolio/elpaca.git"
                              :ref nil :depth 1 :inherit ignore
                              :files (:defaults "elpaca-test.el" (:exclude "extensions"))
                              :build (:not elpaca--activate-package)))
(let* ((repo  (expand-file-name "elpaca/" elpaca-repos-directory))
       (build (expand-file-name "elpaca/" elpaca-builds-directory))
       (order (cdr elpaca-order))
       (default-directory repo))
  (add-to-list 'load-path (if (file-exists-p build) build repo))
  (unless (file-exists-p repo)
    (make-directory repo t)
    (when (<= emacs-major-version 28) (require 'subr-x))
    (condition-case-unless-debug err
        (if-let* ((buffer (pop-to-buffer-same-window "*elpaca-bootstrap*"))
                  ((zerop (apply #'call-process `("git" nil ,buffer t "clone"
                                                  ,@(when-let* ((depth (plist-get order :depth)))
                                                      (list (format "--depth=%d" depth) "--no-single-branch"))
                                                  ,(plist-get order :repo) ,repo))))
                  ((zerop (call-process "git" nil buffer t "checkout"
                                        (or (plist-get order :ref) "--"))))
                  (emacs (concat invocation-directory invocation-name))
                  ((zerop (call-process emacs nil buffer nil "-Q" "-L" "." "--batch"
                                        "--eval" "(byte-recompile-directory \".\" 0 'force)")))
                  ((require 'elpaca))
                  ((elpaca-generate-autoloads "elpaca" repo)))
            (progn (message "%s" (buffer-string)) (kill-buffer buffer))
          (error "%s" (with-current-buffer buffer (buffer-string))))
      ((error) (warn "%s" err) (delete-directory repo 'recursive))))
  (unless (require 'elpaca-autoloads nil t)
    (require 'elpaca)
    (elpaca-generate-autoloads "elpaca" repo)
    (let ((load-source-file-function nil)) (load "./elpaca-autoloads"))))
(add-hook 'after-init-hook #'elpaca-process-queues)
(elpaca `(,@elpaca-order))

(elpaca elpaca-use-package
  ;; Enable use-package :ensure support for Elpaca.
  (elpaca-use-package-mode))

Emacs makes heavy use of modes and it has become good practice to simply create your own minor mode with a corresponding keymap which, I use to bind
my global keys in, instead of the normal global keymap. This minimizes surprises with my custom keybindings.

** Keys
I use the venerable [[https://github.com/noctuid/general.el][general]] package to define my keys. This gives me a flexible way to bind keys for evil while still relying on the ~use-package~ way of bringing packages in.
The configuration is build around a couple of fundamental facilities that allow me to make it much more consistent, discoverable, less surprising but still compatible with Emacs.

*** Key Prefixes

1. =SPC= as the global leader prefix (=C-SPC= as fallback)
2. =SPC m= as the local leader prefix 
3. =SPC .= as the point-local leader prefix
4. =SPC g= as the prefix for =goto= commands. Registered in the =goto-map= which is also available via =M-g=.
5. =SPC s= as the prefix for =search= commands. Registered in the =search-map= which is also available via =M-s=.

*** When to use keybindings vs. invoking the command via =M-x=?

The rule is that I have to use the command frequently, otherwise I don't bother providing a keybinding and rely on Emacs command facility.
